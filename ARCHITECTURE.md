# daedalus — repo card

WHAT: the agent runtime. An agent is a directory (bundle: agent.yaml + persona.md + agent-card.json, optional guardrails.md, skills/, tools/, knowledge/); daedalus loads it and serves it over CLI / A2A / Slack, with tool allowlists, approval gates, enforcement hooks, and optional techne memory.
STATE: main, v0.8.0 (2026-11-14; version lives in src/daedalus/__init__.py; pyproject reads it via [tool.hatch.version]); everything since is under CHANGELOG [Unreleased]. 0.8.0 (PRs #260, #261, #262, #263) is the Slack release: another Slack app's @-mention wakes an agent as a colleague's ask, bounded per thread and per sending app (`SLACK_BOT_MENTIONS`, #260), which changes what an agent already in a channel with other apps does, hence the minor bump; a person's upload in a followed thread reaches the agent (#261); a reaction with a named emoji wakes it (`SLACK_WAKE_EMOJI`, #262); and an agent can post, offer choices as buttons, pin and bookmark, with a click and a slash command reaching it over `/slack/events`, the command answered only where the agent is unless `SLACK_COMMAND_PUBLIC` is on (#263). 0.7.1 (PRs #251, #253, #254, #255) adds `audit.trace`, the access-provenance chain run in a fixed order (#255), reply-aware `slack.find_threads` and author/reaction-aware `slack.read_thread`, account creation in `cloudtrail.query_provisioning`, the bundle pulled from a registry artifact at start and litestream run from the runtime image (#253, tenishai/kobo#434), the `optional: true` slack block that waits for a token instead of failing boot (#253), the face on streamed Slack replies (#251), and moves the bridge's mcp>=2.2 out of the `claude-code` extra into `bridge` (#254, tenishai/ergon#34). 0.7.0 (PRs #225, #226, #238, #239, #241, #243, #248, #249) adds per-task workspaces and metadata-bound tool arguments with `daedalus run --metadata` (#247), engine.claude_code.cwd (#242), model.thinking kept apart from max_tokens (#240), the agent's face on Slack messages (#249), Slack events over HTTP (#239), a leased cloudtrail credential (#225) and embedded MCP resources in tool results (#238); GOTCHAS:
- Never add a module-scope import of an optional extra (fastapi, slack_sdk, mcp, claude_agent_sdk, techne, liminal). Dev env has them all, so CI won't catch it.
- The three techne-path test files (92 tests) collapse to 3 `s` under importorskip. A green default CI run did NOT run them. Use `pytest -rs`.
- `enforcement.py` is the hook LAW layer (bundle/tools/*.py pre_task/post_draft), NOT the three-tier approval model and NOT LLM tools. Tiers 1-2 live in agent.py.
- `bundle/tools/` = enforcement hooks; `tools:` in agent.yaml = LLM tool providers. Same word, unrelated.
- Engine choice is the OPERATOR's (--engine / DAEDALUS_ENGINE), never the bundle's; the bundle only carries engine.claude_code settings. Agent.__init__ checks the engine-specific ones at load: per_task_tokens is refused under claude-code, and a claude_code.cwd that isn't a directory fails the load (#242).
- Every engine run has a deadline (#201): Agent._loop wraps it in asyncio.timeout(spec.task_timeout, default 600 s) and a run past it fails 704; the litellm engine also passes model.request_timeout (default 120 s) to litellm, whose own default is 6000 s. The cancellation reaches a running tool call only because nothing on the call path catches BaseException: keep Agent._call_tool's `except Exception`, and don't add `except BaseException` to a tool provider. A tool that runs in a thread (asyncio.to_thread, e.g. cloudtrail) is abandoned, not stopped.
- `approvals.ceiling.write` and `.hosts` are parsed but read nowhere; don't describe them as controls. Only `ceiling.exec` is read, at load, where it gates the exec builtin (docs/design.md §3 says the same).
- No code sets TaskState.INPUT_REQUIRED and nothing emits reason 700; escalation ends a task FAILED with 704 (design.md §3 says so since #203).
- Tools are built once per process, except builtin groups whose roots use `{workspace}` (#247): those resolve per task from metadata `daedalus_workspace` through a contextvar set in Agent._run_engine. Don't read `current_workspace` outside a task turn; it is None there.
- docs/bundle.schema.json must be regenerated (`daedalus schema --out docs/bundle.schema.json`) with any AgentSpec change, or test_schema fails.
