# approvals — what a model may call, and what a reply may say

WHAT / SEAM: two independent layers, both fail-closed.
1. Tool approval (agent.py): tier 1 = `tools.allow` fnmatch patterns (Agent._allowed_tools, at listing; re-checked in _call_tool at call time). Tier 2 = `approvals.gates[].match` fnmatch → `Approver.approve(name, plan)` with plan {tool, arguments, require}. `tools.bind` arguments (#247) are filled from task metadata before tier 2, so a gate's plan shows the real bound values; the model never sees them in the listing. Engine-native tools (Claude Code built-ins, named `claude.<Tool>`) go through Agent._approve_native (tier 2 only; tier 1 for them is builtin_tools).
2. Law hooks (enforcement.py `Enforcement`): bundle/tools/*.py modules exposing `pre_task(message)` and/or `post_draft(draft)` or `post_draft(draft, record=None)` (a second positional parameter asks for the run record, #268; write it with the `=None` default: a required second parameter raises on a runtime older than #268, a hook that raises blocks every reply, and the room runs mixed runtime versions), loaded at boot, run by Agent.handle_task around the model loop. kobo stages these files ("Tooling door"); the operator tool lane writes more into `<memory.home>/tools-overlay/`.
OPS / FLOW: handle_task → system-task markers dispatched first (see a2a-wire) → if Enforcement.locked: FAILED 703 → run_pre_task (block → 703; notices → system prompt) → memory recall → Agent._messages (system = persona, then the owners' `## Rules` block when guardrails.md or a live write gives any (guardrails.py, rendered at boot and on each write, never per task), then a `## Clock` section holding `Current time (UTC): <Weekday> <ISO>` plus `Yesterday:` and `Past week:` lines, all from one pod-clock reading per task, then a state-today's-date-first instruction, #171/#175/#181/#184, ahead of the skills index so it never reads as a skill, #173 + skills index + recalled context + notices; then the history, where a user turn with a `sender_label` (a Slack person's, transports/slack.py) goes to the model as `(From <label>.)` above its text, while run_pre_task and recall read Task.user_text(), the words alone, since a hook may take the first email in a message as the subject of the ask) → _loop: allowlist (a provider raising → FAILED "tool provider unavailable"; a ToolProviderRefused inside MultiToolProvider drops that provider's tools instead, + prompt note, event tool_provider_refused; #156) → withhold gated tools when approver is DenyAll (+ prompt note, event tools_withheld) → when inbound cabal_delegation_depth ≥ 1 (answering a colleague) keep only tools whose provider declares `knowledge_only = True` (Agent._knowledge_only; skills.load today; MultiToolProvider.provider_of names the owner; colleagues.ask_colleague never counts, #149) + prompt note naming the asker from `daedalus_asked_by`, events colleague_ask_withheld_inbound and tools_withheld_for_colleague (kobo#310) → engine → call_tool: not in allowed set → "error: unknown or disallowed tool" (outcome error); gate denies → "blocked: … requires approval" (outcome blocked); provider raises ToolCallBlocked (a gateway policy refusal) → "blocked: …" (blocked); provider exception → "tool error: …" (error); else the provider's text, outcome as the provider set it on a ToolResult, or ok/empty by whether the text is blank → run_post_draft (block → discard draft from history, 703; else text replaced by hook output; the learnings operator lane runs its JSON reply through post_draft too, #142) → append "_(consulted: …)_" if colleagues were asked but unnamed.
INVARIANTS:
- Agent._call_tool turns a provider's Exception into a `tool error:` result but lets CancelledError through, so the task deadline (#201, Agent._loop) cancels a running tool call. Never widen it to BaseException.
- Empty `tools.allow` = no tools at all. The model never sees a tool it can't call; a hallucinated name misses the map.
- DenyAll is the default approver. Only `chat` (CliApprover) and SlackTransport._wire_approver replace it; headless `run`/a2a stay denied. Approver is process-wide: a Slack-wired approver also gates calls arriving over a2a or cli (design.md §3, by design).
- The Slack tools (slack.post_message / offer_choices / pins / bookmarks, tools/slack_actions.py, 2026-11-14) are ordinary tier-1 tools: on with a `kind: slack` transport block, offered only when `tools.allow` matches them, and never on a turn a program asked for (the provider is not `knowledge_only`).
- Unapprovable gated tools are WITHHELD, not offered-then-refused (#105): a model refused every time retries a refusal it can't understand.
- Withholding is per agent, not per gate: it holds only while the approver is DenyAll. Once any approver is wired (one `kind: slack` block with `approvers` and `channel` is enough), every gate, `*` included, is offered and asks per call. A gate keeps write tools away from a read-only agent only under DenyAll (#268; tests/test_agent_tools.py wildcard tests).
- Slack reaction approver: only user ids in the `approvers:` list of a `kind: slack` block may approve (#53, #141; unioned across blocks). No list = every gate denied before a plan is posted. The Slack requester doesn't count as an approver unless they are the only one listed. A ❌ from anyone denies. The transport wires the approver only when `approvers` AND a `channel` allowlist are set; an open transport keeps DenyAll (transports/slack.py _wire_approver).
- Law never half-loads: any hook import failure (image or overlay) locks the Enforcement; every task then fails 703 until fixed. An overlay file shadowing an image hook name is skipped with a warning, not loaded.
- Hooks run on a dedicated 4-thread pool with a 2.0 s timeout (HOOK_TIMEOUT_S). A timeout/exception/unexpected shape = block. 4 is a LIFETIME budget: 4 wedged hooks since boot and the agent stops answering until restart, on purpose.
- pre_task denies by raising OR returning {"blocked": True, "reason": …} (#45); allowed keys are notices/blocked/reason only.
- A blocked post_draft reply is deleted from history, never partially sent: task_to_a2a serializes full history, and persisted tasks feed history back into the model.
- The run record (run_record.py, #268) is built from the task's own trace events (Agent._emit feeds the RunRecorder in `current_recorder`), so it means the same for both engines. The learnings lane passes record=None. Unreported usage is None, and a total is None if any model call went unreported. handle_task logs one INFO line per chat task, `task usage: engine=… model=… turns=… input=… output=… cache_read=… cache_write=…` ("unknown" for None), and emits the same fields once as a `task_usage` event, which cli._print_event prints under -v; that is what reaches a pod's output, since daedalus configures no log handler. The per-call `usage` events are not printed; there is no metric.
- A tool call's outcome comes from the code path, never the text: Agent._call_tool returns a protocols.ToolResult (a str with `.outcome`), the engines put it on the `tool_result` event, and the recorder falls back to the text prefixes only when an event has none. A gateway refusal reads blocked (consult_refusal → ToolResult blocked; liminal's -32001 on a call → ToolCallBlocked; liminal also answers every token failure with -32001, an expired token or a failed JWKS fetch included, so blocked can mean a gateway auth outage). A liminal or direct-MCP result is "empty" when its content blocks hold nothing once liminal's untrusted-result envelope, and a trailing PR 234 empty notice inside it, are set aside (whitespace and zero-width text count as blank) (tools/liminal.py result_is_empty, tools/mcp.py result_is_empty). A Claude Code built-in reads unknown, or blocked when the trace has its permission_denied.
- A post_draft hook's returned text replaces the reply in history, so text a hook adds (a footer) is not only shown once: it is replayed to the model on the next turn of that thread, sent to an agent that consulted this one (the a2a reply is the history), and fed to the learnings summary (the journal is written from the history). Do not add a footer until that is fixed. A hook that reads the record and only logs, or blocks, and returns the draft unchanged is safe.
- No hot reload: a hook delivered over the tool lane is inert until the next boot.
- The tool lane is a code-deploy path (#195): the next boot imports an overlay file and runs its module-level code as the agent, with its env and volumes. memory/tooling.py's checks are a lint (an `__import__("os")` file passes); the operator allowlist (teach_authorized, see a2a-wire) is the only control.
- The `## Rules` block is guidance in the prompt, not a control: nothing checks a reply or a call against it. What must never happen belongs in tier 1 (no tool), tier 2 (a gate) or a law hook. The block is cut from the bottom at 4,000 characters and says how many rules it left out, so a cut list never reads as complete. Its one-line intro (guardrails._INTRO) also says a person's Slack message starts with that `(From Name <email>, in #channel.)` line and that a rule may end with lists, `(These people: ...)`, `(These emoji: ...)`, `(These channels: ...)` or `(These repositories: ...)`, about exactly what they name: people by the email in that line, channels by the channel in it, emoji by the reaction that woke the agent, repositories by the ones its tools act on. The room writes rules that name things that way. Still guidance; the label is as good as users.info and conversations.info, and a2a turns (the room's chat, colleagues) carry none.
- `approvals.ceiling.exec: true` is the bundle's consent to the exec builtin; without it tools.builtin.exec is a BundleError at load. `ceiling.write`, `ceiling.hosts` and `escalation` beyond Slack routing are parsed but unenforced; do not describe them as controls.
CONSUMERS: agent.py (all call sites); engines via EngineTurn.call_tool/approve/withheld; transports/slack.py (SlackReactionApprover, escalation reply formatting); cli.py (CliApprover); A2A card gets `enforcement` stamp (Enforcement.card_stamp: version, hooks, locked) in Agent.transports. kobo writes the hook files; its upload lint is ported into memory/tooling.py (a lint, not a sandbox).
API: Enforcement.load(tools_dir, overlay_dir), .locked, .active, .run_pre_task → PreTaskResult(blocked, notices, detail), .run_post_draft(draft, record=None) → PostDraftResult(blocked, text, detail), .card_stamp().
