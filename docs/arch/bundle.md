# bundle — agent.yaml schema and the bundle directory

WHAT / SEAM: `Bundle.load(path, env=None)` (bundle.py) → Bundle(path, spec: AgentSpec, card: dict, persona: str, skills: dict[str, Skill], guardrails: str). `AgentSpec` (pydantic) is the agent.yaml schema: name, card, persona, model (ModelSpec: id, max_tokens (the visible reply's ceiling, default 8192, gt 0), thinking (ThinkingSpec | None: mode auto|off|on, budget_tokens ≥ 1024; the thinking budget kept apart from max_tokens, #240, litellm engine only; daedalus.llm.thinking_kwargs reads it), request_timeout (s per model call, default 120, litellm engine only, #201), api_base, api_key_env, budget.per_task_tokens; id is required and is either a model or a tier word, fast|balanced|best), transports[], tools (ToolsSpec), memory (MemorySpec: personal none|techne, home, recall_sources [names of installed techne.recall_sources entry points, #265], team, revision), checkpoints, approvals (ceiling, gates, escalation), engine.claude_code (ClaudeCodeSpec: binary, model, builtin_tools, permission_mode, on_denied, config_dir, cwd — the directory Claude Code works in, #242), task_timeout (s per engine run, default 600, #201). `bundle_schema()` emits it as JSON Schema → docs/bundle.schema.json.
Directory: agent.yaml, persona.md, agent-card.json (required); guardrails.md (optional, the owners' rules one per line, read raw into `Bundle.guardrails`; daedalus.guardrails parses and renders it); skills/<id>/SKILL.md (frontmatter when_to_use, description, requires; `Skill.summary` = when_to_use, else description, else name, else id, one line cut at `SUMMARY_MAX_CHARS` 300, and that is the index line); tools/*.py (enforcement hooks, not LLM tools); knowledge/*.md and intake/* (seeded into techne by docker/seeder.py, not by the runtime; a skill seeds as its card, not its body, when tools.allow admits skills.load, `offers_skills_load`).
OPS / FLOW: read agent.yaml → `interpolate` ${VAR} / ${VAR:-default} recursively (undefined without default → BundleError) → AgentSpec.model_validate → require card + persona files → strip persona comments → load_skills. Agent then builds collaborators from spec (see protocols card).
INVARIANTS:
- Unknown fields load with a WARNING, never an error and never silently (`_WarnExtra`): forward-compat with newer writers (kobo, kaminos).
- docs/bundle.schema.json is drift-pinned: tests/test_schema.py::test_committed_schema_cannot_drift_from_the_runtime. Any AgentSpec change needs `daedalus schema --out docs/bundle.schema.json` in the same commit. The schema is the contract for non-Python readers (cabal's bundle reader, editors).
- `tools.allow` empty = deny everything. `tools.provider` ∈ none|mcp|liminal|colleagues picks ONE primary; github, cloudtrail, slack_read, jira, liminal.url are SIDECARS that stack beside it (agent.py _tools_from_spec). A `kind: slack` TRANSPORT block also stacks one, slack_actions (slack.post_message / offer_choices / pins / bookmarks, 2026-11-14): no block of its own, lists nothing without SLACK_BOT_TOKEN, reach = the blocks' `channel` allowlist (open when any block names none) plus the conversation the task was asked in. `cloudtrail` is ON when `event_data_store` plus either `role_arn` (the pod assumes) or `bab_url`+`bab_integration` (a one-hour credential leased from the room's permission service with the token at `bab_token_file`) are set; `CloudTrailSpec.on` is the one predicate (2026-10-29). `slack_read.channels: []` = lane ON for every invited channel; omitted = OFF (2026-09-23). `audit_trace` (2026-11-04) is ON when `tracker_site` + `tracker_project` are set (`AuditTraceSpec.on`) and then REQUIRES cloudtrail and slack_read on (BundleError at wiring otherwise); every org-specific value (tracker tool prefix, group prefixes and noise words, the request bot's thread marker, approval phrase, approver field) lives in the block, none in code.
- Which engine runs a bundle is NOT in the bundle; `engine.claude_code` only configures that engine. Same bundle must run with and without Claude Code.
- `memory.revision` unknown value → warn and disable; absent = the revision module is never imported.
- `memory.recall_sources` (#265) is a list of entry-point names, default empty; TechneMemoryStore adds them to techne's `recall.allowed_sources` in memory on every config load and never writes the memory volume. Golden `tests/golden/diarist/` names `daffyne`.
- A skill whose `requires:` the allowlist doesn't admit, or skills without `skills.load` allowed, warn at load (unmet_requirements); they don't fail.
- Slack transport: `channel` key present but empty → BundleError (a typo must not open the widest reach); key omitted → every invited channel. All slack blocks fold into ONE SlackTransport (Socket Mode delivers each event to one connection).
- model.id as a tier (#127, #129) resolves at Agent construction from the deployment's tiers file ($DAEDALUS_TIERS, tiers.py): the entry fills model.id, the endpoint fields, max_tokens/thinking/request_timeout, context_tokens/max_repeats and the claude-code model, never overriding a value the bundle set (model_fields_set decides; model.thinking None = silent); no tiers file → BundleError. tiers.py imports ThinkingSpec from bundle.py, never the reverse. The old model.tier/min_tier keys are refused with a pointer to model.id.
- tools.builtin groups are `files` and `exec`; exec loads only with approvals.ceiling.exec: true (agent.py), anything else is a BundleError. The field stays an untyped dict (agent.py passes each block as provider kwargs); its schema `description` is where an author sees the refused files roots (tools/builtin.py _refused_root, #199). request_timeout, salvage_text_calls and task_timeout carry descriptions too.
- Per-task workspaces (#247): `tools.workspace.parent` plus a builtin root written as the literal `{workspace}` or `{workspace}/sub` (not a ${VAR}: filled per task, never at load). Task metadata `daedalus_workspace` names ONE folder under the parent (regex `[A-Za-z0-9][A-Za-z0-9._-]*`, resolved after symlinks, must exist); anything else fails the task 701 before any tool is listed (agent.py _run_engine). The token without a parent, a parent that isn't a directory (checked at load whenever it is set, since the Claude Code engine runs in the workspace), or a sub-root with `..` fail at load; a parent gone after load fails the task 701. tools/workspace.py holds the resolver and WorkspaceToolProvider, which builds the real files/exec provider per workspace from a contextvar (cached, 32 entries).
- `tools.bind` (#247): {tool: {argument: dotted.metadata.path}}. Agent._run_engine_turn hides bound arguments from the listing the engine gets and overwrites them on every call, before the gates; a missing or empty value fails the call, never falls back to the model's value. A bind key matching no offered tool emits `bind_unmatched` per turn.
- tools.salvage_text_calls (#200): None = on only when model.api_base is set; salvage reads only JSON inside <tool_call>/<tools> tags (engines/litellm.py).
- Fields validated at load so a typo fails the bundle: slack `approvers` (list of U…/W… user ids), slack `wake` (mention|thread|channel; every slack block must agree), github.branch_prefix (a valid git ref component, default "daedalus"), memory.team (only "none"; "outbox" is refused because it was never built).
- The schema lets `${VAR}` / `${VAR:-default}` placeholders stand in for enum, integer, number and boolean leaves (#132), so an editor accepts what interpolate() will expand.
- Golden bundles tests/golden/<name>/ are fixtures AND worked examples; new format features want one.
- ThinkingSpec.mode takes a bare YAML `off`/`on` (YAML 1.1 booleans) as the word, via a before-validator; without it `thinking: {mode: off}` in a tiers file failed with "Input should be 'auto', 'off' or 'on'" (#240). The greeter golden carries a thinking block.
- Both timeouts (#201) are positive numbers with no "off" value: a bundle can raise them, never remove them. The greeter golden sets both. kobo vendors docs/bundle.schema.json, so these two fields reach it only when it re-vendors.
CONSUMERS: agent.py (Agent.load, _tools_from_spec, transports()); cli.py (`schema`, `create` via scaffold.py); kobo composes bundles (kobo_api/steps.py) and pushes them as repos; cabal reads bundles via the JSON Schema; docker/seeder.py reads knowledge/, skills/, intake/.
API: Bundle, AgentSpec (+ nested *Spec classes), BundleError, bundle_schema(), interpolate(), load_skills(), unmet_requirements(), strip_persona_comments().
